VIWOODS AiPaper Reader C 的免登入 AI 架構、GPT 存取方式、可能的授權機制、使用上限與隱私邊界評估

裝置：AiPaper Reader C 範圍：GPT 與內建雲端 AI 判定方式：官方資料 + 技術架構推論

1執行摘要

官方已確認 合理技術推論 尚未公開 風險／限制

核心結論

使用者未登入，不代表 GPT 完全沒有驗證。比較合理的解釋是：Reader C 透過內建 AI 用戶端、裝置身分或服務權杖取得模型存取權；GPT 的授權、費用與 API 配額由 VIWOODS、合作平台或模型供應商的企業方案處理，因此終端使用者不需要 VIWOODS、ChatGPT 或 OpenAI API 帳號。

目前無法確認的部分

VIWOODS 沒有公開 Reader C 實際使用的 API 網路架構、裝置憑證格式、是否經第三方 AI 聚合平台、每台裝置配額，以及未登入與登入狀態是否有不同額度。因此本報告會把確定事實與合理推論分開呈現。

2「不用登入」真正代表什麼？

常見誤解 沒有帳號，所以沒有驗證

若完全沒有服務驗證，任何人都能偽造請求並耗用模型額度，無法控制成本或濫用。

較合理的實際定位 免使用者登入，但仍有裝置／服務驗證

系統可以辨識合法裝置、建立匿名工作階段並分配 AI 額度，而不用知道使用者姓名或 Email。

三種帳號或身分層級必須分開

  • VIWOODS 使用者帳號：用於裝置綁定、Web Search、同步與雲端功能。
  • ChatGPT 個人帳號：用於 ChatGPT 網站與 App，不是硬體廠商整合 GPT API 的必要條件。
  • 模型服務授權：由裝置、廠商後端、企業專案或第三方平台持有；使用者通常看不到。

為什麼不應直接把永久 OpenAI API Key 放在裝置內？

行動裝置中的程式與韌體可能被分析；若內嵌完整 API Key，攻擊者可能擷取金鑰並冒用額度。OpenAI 官方建議不要在瀏覽器或行動 App 中部署 API Key，而應透過安全的後端系統處理。因此 Reader C 若使用 OpenAI API，較可能採取後端代理、短效權杖、企業 SDK 或裝置憑證，而不是所有裝置共用一把永久明碼金鑰。

4可能採用的技術架構

可能架構運作方式評估
VIWOODS 後端代理 裝置先向 VIWOODS 服務驗證，再由後端持有 API 憑證並呼叫 GPT。 常見做法 但與「資料不經 VIWOODS 伺服器」的宣稱需要進一步釐清。
裝置憑證＋短效權杖 出廠憑證證明裝置合法，服務只發放短時間有效的模型存取權杖。 可能性高 可避免保存個人帳號，也較容易限制單台裝置。
第三方 AI 聚合平台 合作平台統一連接 GPT、Gemini、DeepSeek，並處理模型路由、計費與限流。 可能性中高 符合單一介面切換多模型的產品設計。
模型供應商 OEM 授權 VIWOODS 與模型供應商簽訂裝置或企業授權，使用權隨硬體提供。 可能 但合約方式與配額沒有公開。
匿名試用／預設額度 每台新裝置取得一組匿名額度，達到條件後限流、等待重置或要求登入。 未證實 裝置介面沒有公開固定額度不代表不存在。
本機與雲端混合 字典、歷史紀錄或部分文字處理在本機完成；複雜問答與摘要送到雲端。 部分可能 GPT 回答本身仍需網路與雲端模型。

5為什麼使用者暫時不需付費？

可能的商業原因

  • 成本包含在硬體售價：購機收入補貼一定期間或合理用量的 AI 成本。
  • OEM 大量採購：企業方案的單次模型成本可能低於個人直接使用的感受。
  • 動態選擇低成本模型：簡單問題可使用較小模型，只有複雜任務才使用較昂貴模型。
  • 推廣期補貼：AI 可能作為產品差異化功能，由行銷預算暫時吸收。
  • 共享服務容量：不是每台裝置各買一份訂閱，而是大量裝置共用企業專案。

「No Subscription Fee」不等於永久無限

免額外訂閱只代表目前沒有向使用者另外收月費；廠商仍可透過合理使用政策、伺服器負載、模型成本、區域、韌體版本或防濫用規則調整服務。

6AI 使用上限從哪裡產生？

限制層可能採用的限制影響
模型供應商 RPM、RPD、TPM、TPD、模型並行量、專案月額度。 超過後可能暫時拒絕請求、回應變慢或等待重置。
VIWOODS／合作平台 每台裝置每日次數、每次輸入長度、最大回答 token、特定模型配額。 可能顯示服務繁忙、請稍後再試，或切換至較低成本模型。
匿名裝置身分 依裝置憑證、安裝 ID、序號雜湊、Android ID 或匿名 UUID 計量。 登出、清除 App 資料或更換網路未必能重置額度。
網路與防濫用 IP 頻率、異常大量請求、自動化行為、地區及伺服器負載。 可能暫時限流、封鎖或要求等待。
裝置功能 語音錄音時間、單次上下文長度、可用模型清單與韌體限制。 屬單次使用限制，不等於每日使用額度。

OpenAI API 限制不是依 Reader C 使用者帳號計算

OpenAI 官方文件指出，API rate limit 主要設定在組織與專案層級，並依模型區分；可使用每分鐘／每日請求數與 token 數等指標。若 VIWOODS 使用 OpenAI API，實際上限首先取決於其企業組織或專案，再由 VIWOODS 或合作平台分配到裝置。

8隱私與安全邊界

免登入不等於完全匿名

  • 服務可能看見 IP 位址、裝置類型、韌體版本、匿名工作階段或裝置識別資訊。
  • 為了計量與防濫用，系統可能以無法直接顯示姓名的裝置 ID 建立使用紀錄。
  • 即使對話主要保存在本機，送給雲端模型的提示內容仍必須離開裝置進行推論。
  • 「資料不經 VIWOODS 伺服器」不代表第三方模型或合作平台不會處理提示內容。

不建議送入的內容

在沒有完整資料流、保存期限及第三方處理政策前，不建議輸入密碼、API Key、客戶個資、未公開公司資料、醫療紀錄或其他高度敏感內容。

9若要進一步確認實際架構

可向 VIWOODS 客服詢問

  1. GPT 是直接連接 OpenAI，還是經第三方 AI 聚合平台？
  2. 未登入裝置以何種識別方式計算配額？
  3. 每天／每月是否有問題數或 token 上限？
  4. 登入與未登入是否有不同模型或額度？
  5. 提示內容會經過哪些伺服器、保存多久、用於哪些目的？
  6. 停止支援或更換模型時，是否會通知使用者？

技術檢查能確認什麼

在合法且不解密敏感內容的前提下，可透過 DNS 紀錄、網路連線目的網域、Android 系統日誌與 App 權限判斷服務可能連往何處。但因 HTTPS 會加密內容，僅看到網域通常仍不足以證明真正的模型供應商、帳單歸屬或完整資料處理鏈。

10最終判定

Reader C 的「免登入 AI」本質上是免除使用者帳號，而不是免除服務授權。

最可能的模式是由合法裝置身分、短效權杖、企業 API 專案或第三方 AI 平台承擔 GPT 的驗證與計費，使用者只需連網即可呼叫。使用上限可能存在於模型供應商、VIWOODS 服務、匿名裝置 ID、網路防濫用與裝置功能等多個層級。由於 VIWOODS 尚未公布固定每日次數、token 額度及完整 API 架構，目前只能判定「一般使用可用，但不能視為永久且完全無限量」。
